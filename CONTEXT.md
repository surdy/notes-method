# Notesmith Domain Glossary

This file defines the domain vocabulary used throughout the Notesmith codebase. Use these terms consistently in code, comments, issues, and architectural discussions.

---

## Vault & Notes

- **Vault** — A rooted directory of markdown notes with a `.notesmith/` config folder. A user may have multiple vaults (e.g. `work`, `personal`). Each vault is independently configured and indexed.
- **Note** — A single markdown file in a vault. The canonical parsed representation including frontmatter, body, tasks, links, inline fields, and blocks. (`notesmith-core::Note`)
- **VaultPath** — A vault-relative path to a note, e.g. `Daily/2025-01-15.md`. Never absolute. (`notesmith-core::VaultPath`)
- **VaultName** — A short identifier for a vault, e.g. `work`. Used in API paths and config. (`notesmith-core::VaultName`)
- **VaultEngine** — The filesystem abstraction trait for scanning, reading, writing, deleting, and moving notes. (`notesmith-core::VaultEngine`)

## Frontmatter & Fields

- **Frontmatter** — YAML metadata at the top of a note, delimited by `---`. Parsed generically as key-value pairs (no typed variants). (`notesmith-core::Frontmatter` → `HashMap<String, Value>`)
- **Field** — A key-value pair associated with a note. Sources: frontmatter YAML or inline `[key:: value]` syntax. All fields are stored uniformly in the `fields` table with no source distinction in queries.
- **Tag** — A label associated with a note. Sources: `tags:` frontmatter array or inline `#hashtag` syntax. Stored in a dedicated `tags` table for ergonomic multi-value queries.
- **Field Registry** — Advisory field definitions in `.notesmith/fields.toml`. Specifies type, allowed values, and autocomplete sources for each field key. Not enforced — invalid values produce warnings.

## Tasks

- **Task** — A checkbox item extracted from note content. Has status character, status group, text, and a source position linking back to the note.
- **TaskStatus** — Configurable and extensible. Each status is a single character (e.g. `x`, `/`, `!`) mapped to a label, group (`open` or `done`), and icon via `[task_statuses]` in `vault.toml`. Default ships the standard OFM set: `[ ]`=Todo, `[x]`=Done, `[/]`=InProgress, etc.
- **Task Fields** — Inline fields associated with individual tasks (e.g. `[due:: 2026-06-01]` on a task line). Stored in a `task_fields` table.

## Links & Blocks

- **Link** — A parsed reference from one note to another. Types: wiki (`[[target]]`), embed (`![[target]]`), heading ref, block ref, anchor, markdown link, external.
- **InlineField** — A `key:: value` pair embedded in note text, used for metadata that doesn't belong in frontmatter.
- **Block** — A content block with an optional block ID (`^block-id`) for block-level references.
- **SourcePosition** — Line/column/offset/length anchor for any parsed syntax element back to its source location.
- **Backlink** — An inverse link: "which notes link to this note?"

## Indexing & Search

- **NoteIndex** — The in-memory SQLite cache of all parsed notes, tasks, links, and frontmatter. Rebuilt on startup, incrementally updated on file changes. (`notesmith-index`)
- **SearchIndex** — The Tantivy full-text search index alongside the NoteIndex. (`notesmith-index`)

## Configuration

- **VaultConfig** — Per-vault settings in `.notesmith/vault.toml`. Sections: schema version, capture, periodic notes, editor, git, hooks, task statuses.
- **GlobalConfig** — App-wide settings in `~/.config/notesmith/config.toml`. Contains daemon bind address, CLI auto-start policy, the vault registry, an optional `[agents]` section for agent discovery (per-id launch overrides, custom ACP agents, and a `debug` diagnostics flag), and an optional `[mcp]` section (`[[mcp.servers]]`) listing external MCP servers (id, transport `command`/`url`, args, env, `headers` — HTTP request headers with `$VAR`-expanded values for auth-protected servers, issue #283 — enabled) the agent sees alongside the built-in vault tools (ADR 0016, issue #211).
- **SidebarConfig** — Per-vault sidebar view definitions in `.notesmith/sidebar.yaml`. Defines custom views with sections (recently-viewed, custom-folders, custom-items).
- **Quill Rail File Tree** — The Files tab's folder-icon-free typographic tree (`FileTree.svelte`). Subtle disclosure triangles identify folders; vertical rails plus short horizontal Branch Spine connectors expose nested structure; explicit note `_icon` values remain visible; selection uses a narrow accent spine.
- **Files Toolbar** — The compact action row at the top of the Files sidebar (`SidebarViews.svelte`): note search plus New Note, New Folder, and Refresh buttons. New Note uses the shared two-step input palette (title + folder); New Folder creates/opens the folder's same-name folder note so the notes-derived tree can represent it immediately.
- **RoutingConfig** — Per-vault routing rules in `.notesmith/routing.yaml`. Expressive YAML DSL with boolean combinators (all/any/not), field/tag predicates, and full mutations (move, set/remove fields, add/remove tags).
- **FieldRegistry** — Per-vault field definitions in `.notesmith/fields.toml`. Advisory type/value constraints for autocomplete and validation.
- **UserViews** — Per-vault SQL view definitions in `.notesmith/views.sql`. Creates persistent views in the cache database for dashboard blocks and queries.

## Capture & Routing

- **Capture** — A first-class command that writes timestamped notes to the configured capture folder. Delegates to the template system internally. When `capture.folder = ""`, captures land in the vault root.
- **Web Clip** — "Capture, but from a URL." The daemon fetches a web page (SSRF-guarded, bounded), extracts the readable article (`notesmith-clip`: readability + HTML→Markdown), and writes a Markdown note with provenance frontmatter (`source_url`, `source_type: article`, `title`, `author`, `published`, `ingested_at`) tagged `inbox` so routing files it. Deduplicated by canonical `source_url`. Optional per-domain minijinja templates and image download via `[clip]` config. Triggers: `POST /api/v/{vault}/clip`, `notesmith clip <url>`, and the `ui/extension/` Manifest V3 browser extension. Amends ADR 0019 §4 for user-initiated fetches; see ADR 0020.
- **Drop-Folder Ingestion** — "Capture, but from a folder." A colocated `notesmith ingest` worker (`notesmith-ingest`) scans each vault's raw drop folder (`[ingest] raw_dir`, default `raw/`) for documents an external tool dropped in, extracts their text (reusing `notesmith-document`: PDF/EPUB), and writes a provenance-tracked sidecar note under `[ingest] notes_dir` (default `ingested/`) with frontmatter (`source_path`, `source_type`, `source_hash`, `source_mtime`, `ingested_at`, `status`). Raw files are **kept in place** — never moved, renamed, or deleted. Identity and staleness derive from `(source_path + source_hash)`; the sidecar note is the durable processed-state ledger. Each pass also appends one greppable line per **state-changing** action (`ingested`/`reingest`/`renamed`/`failed`/`unsupported`) to a per-vault append-only human-readable ledger at `raw/log.md` (#264); steady-state no-ops are skipped so it stays a meaningful audit trail, and it is purely derived observability (deleting it is always safe, and it is never re-ingested). Per-item failures are recorded (`status: failed`/`unsupported`) and never abort the batch (ADR 0009). Runs on demand via `notesmith ingest`; when `[ingest] enabled = true` the daemon also **supervises a per-vault scheduler that shells out to `notesmith ingest` on an interval** — keeping heavy extraction out of the daemon process (ADR 0022 §7). Ingested notes are ordinary Markdown the embed worker picks up automatically. See ADR 0022.
- **Transcription (`notesmith-transcribe`)** — Engine-agnostic speech-to-text core (ADR 0023). Owns the `Transcriber` trait boundary and the `AudioInput` / `Transcript` / `TranscriptSegment` / `TranscribeError` data model, mirroring `notesmith-embed`'s `Embedder`. Two engines keep it swappable: **`StubTranscriber`** (deterministic, model-free — the default in lean builds and tests) and **`LocalWhisper`** (real whisper.cpp via `whisper-rs`, behind the off-by-default `local-whisper` Cargo feature so the standard gates never compile the C/C++ backend). `LOCAL_WHISPER_COMPILED` is the single capability constant (mirrors `LOCAL_EMBED_COMPILED`); `NOTESMITH_WHISPER_MODEL_DIR` resolves a bundled `ggml-*.bin` model like `bge-small`. This crate also owns the **shared transcript → note renderer** (`format_timestamp`, `transcript_body`, `render_transcript_note` with ADR 0019 §3 media-provenance frontmatter); `notesmith-clip` depends up on it and re-exports `TranscriptSegment` so YouTube captions and transcribed audio share one body format. Surfaced via the `notesmith transcribe <audio>` CLI (single-file) and `notesmith transcribe --drain` (queue worker). The **pending-transcription queue** (`transcribe.db`, a per-vault worker-domain SQLite table keyed by canonical `source_url`, mirroring `embeddings.db`) is drained by **`TranscribeWorker`** into notes under the vault's `[transcribe] notes_dir`; the daemon **enqueues only** (ADR 0023 §5) — a supervised `transcribe_scheduler` shells out to the CLI worker per vault on an interval (gated by `[transcribe] enabled`), keeping heavy inference out of the daemon process (mirrors the ingest scheduler). The clip `NoCaptions` branch appends a `youtube` intent row; the worker then acquires the audio via an `AudioAcquirer` seam — `YoutubeAudioAcquirer` (in `notesmith-clip`, injected by the CLI) fetches the InnerTube player, selects the smallest MP4/AAC audio-only stream, downloads it bounded + SSRF-guarded, and decodes to mono 16 kHz PCM (symphonia decode behind the off-by-default `youtube-audio` feature; lean builds short-circuit with `Unsupported`) — ADR 0023 P2c. `/api/capabilities` advertises a `transcription.compiled_in` block. Alternative engines (e.g. Parakeet) can be added purely by implementing `Transcriber`.
- **Routing** — Rule-based note filing using an expressive YAML DSL (`.notesmith/routing.yaml`). Rules match on field values, tag presence/absence, path globs, and boolean combinators (all/any/not). Mutations: move_to, set_fields, remove_fields, add_tags, remove_tags. Supports both manual trigger (`notesmith route apply`) and auto-routing (opt-in per rule).
- **Route Log** — An append-only audit table recording every routing operation (from_path, to_path, rule_id, mutations). Enables undo via `notesmith route undo`.
- **Daemon-backed CLI commands** — `capture`, `clip`, `query`, `note`, `search`, `template`, `route`, `periodic`, `task`, `reindex`, `daily`, `url-open`, and `mcp start`. They resolve a daemon base URL (the global `--url` flag or `NOTESMITH_URL` env var when set, otherwise the local bind) and, for the local daemon, probe `/api/status` and auto-start it when `[daemon].auto_start = true`. A remote target (`--url`/`NOTESMITH_URL`) is used verbatim and never auto-started; the `daemon` lifecycle subcommands always manage the local daemon. Base-URL resolution is centralized in `notesmith-cli`'s `daemon_client` (`resolve_override`/`set_remote_override`).

## Templates

- **Template** — A Minijinja-backed markdown file in `.notesmith/templates/` (legacy `Assets/templates/` is still supported) with metadata (name, description, output path pattern), prompt specs, optional context_queries (SQL), and optional pre_render_hook (script). (`notesmith-templates::TemplateEngine`)
- **PromptSpec** — A named parameter a template requires at instantiation time (e.g. "customer name", "meeting date"). Types: `text` (free input) and `field-picker` (existing values of a registered field, from its `values` or `suggest_from` query, while still accepting a new one). A picker's `field` names the `fields.toml` key to suggest from, defaulting to the prompt name — set it when they differ, e.g. a singular `customer` prompt suggesting from the plural `customers` list field.
- **RenderedTemplate** — The output of template instantiation: a resolved path and rendered content.
- **Context Layers** — Three layers of template context: (1) static variables (date, vault, filename), (2) SQL context_queries against the cache, (3) pre_render_hook script enrichment.

## Kits

- **Kit** — An installable vault configuration: `.notesmith/` config, templates, dashboards, and a folder skeleton, embedded in the binary and written into a vault by `notesmith kit apply` or by passing `kit` to `POST /api/app/vaults` (ADR 0024). A kit *configures* a vault; it never ships notes. (`notesmith-kit::Kit`)
- **Work Notes kit** — The blessed kit (`kits/work-notes/`, documented in `docs/example-work-notes-kit.md`): meetings, customers, streams, people and tasks, with `kind` as the canonical type field and relationships in frontmatter wikilink lists. Its files are **byte-identical to `golden-vault/.notesmith/`** (enforced by test), so the fixture's suite — routing destinations, template rendering, periodic matching, dashboard SQL — covers what users install.
- **Apply** — Writing a kit into a vault. Non-destructive: an existing file is reported as skipped, never overwritten without `--force`, so applying to a populated vault is safe and re-applying is a no-op. `{{ vault_name }}` in kit files is substituted at write time.

## Periodic Notes

- **Periodic Note** — A note tied to a time period (daily, weekly, monthly, quarterly, yearly). Generated into configured folders from templates.
- **Period Kinds** — Five types: daily (`YYYY-MM-DD`), weekly (`YYYY-Www`), monthly (`YYYY-MM`), quarterly (`YYYY-Qq`), yearly (`YYYY`). Each configured independently in `vault.toml` with folder, template, and filename pattern.
- **DailyScheduler** — Background task that auto-generates daily notes at a configured time (also available for other period kinds).

## Runtime & Events

- **Daemon** — The HTTP server process (`notesmith daemon start`) that serves the API, SSE events, and static frontend when frontend assets are available.
- **Container image flavors** — GHCR publishes an `app` flavor (`latest`, `sha-*`, date tags) with the SvelteKit frontend at `/app-ui` for browser `/app/` access, and an `api` flavor (`api-latest`, `api-sha-*`, date tags) with only the Rust binary. Each also has an embed-capable `*-embed` counterpart (`latest-embed`, `api-latest-embed`, …) built with the `local-embed` feature for semantic search (ADR 0018 §9.2). The Tauri desktop can use either flavor: when a window is connected to a remote server (see **Connection Management**), the desktop serves the frontend from embedded assets and sends only API/SSE traffic to the daemon.
- **MCP server** — Exposes the vault to MCP clients in two ways: daemon-hosted streamable-HTTP endpoints mounted per vault at `/mcp/<vault>` (full) and `/mcp-ro/<vault>` (read-only) that reuse the daemon's live indexes, and the `notesmith mcp start` command which is a **stdio↔HTTP bridge** to those endpoints (it forwards every stdio request to the daemon; no embedded in-memory index path). Both map MCP tool/resource requests onto the shared `notesmith-ops` operations layer (`NotesmithMcp` wraps an `Arc<dyn Ops>`; the bridge holds a `Peer<RoleClient>` to the daemon). See ADR 0010.
- **Vault lint / knowledge-health** — Read-only signals an ACP agent composes into a health pass (contradictions, stale claims, orphans, missing cross-links, concepts with no note; issue #265, ADR 0015 — no daemon LLM). Orphans + top-backlinks come from the `vault_stats` MCP tool; **`v_dangling_links`** (SQL view, `notesmith-index` schema) exposes wikilink/embed/heading/block-ref targets that resolve to no note (the complement of `v_backlinks`, same resolution rules), queried via `query_sql`; near-duplicate/missing-link candidates come from `vault_search`. Lint is read-only by default — findings are surfaced, edits are a separate explicit step. See `docs/mcp.md` (Vault lint agent workflow) and `docs/sql-views.md`.
- **Ops layer** — `notesmith-ops` defines the canonical vault-operation surface. `Ops` is the trait (read + write methods); `LocalOps` is the in-process implementation backed by engine/cache/search index/template engine; `ReadOnlyOps<O>` wraps any `Ops` and rejects every write (used to expose read-only agent surfaces without auth). See ADR 0010.
- **Embeddings / semantic search (`notesmith-embed`)** — Optional vector-search layer (ADR 0018). A colocated `notesmith embed` worker walks the vault, chunks notes (~256–512 tokens with citation offsets), and writes vectors + provenance to a durable, worker-owned `embeddings.db` (`data_dir/<vault>/embeddings.db`, outside both the vault and the rebuildable `cache.sqlite`); it re-embeds only where `content_hash` changed. The daemon opens that DB **read-only** and embeds queries in-process. Two traits keep the design swappable: **`Embedder`** — `HashEmbedder` (deterministic 384-dim, non-semantic, the default so tests/CI/lean builds need no model download) or `LocalFastEmbed` (real `bge-small-en-v1.5`, 384-dim, behind the `local-embed` Cargo feature); `notesmith_embed::default_embedder()` is the single factory the worker and query path share so `embedder_id`/`dim` always agree (a mismatch fails loud). **`VectorStore`** — currently `BruteForceStore` (linear cosine scan; sqlite-vec/LanceDB deferred behind the trait). `EmbeddingSearch` ranks query-vs-chunk similarity and resolves metadata via an `ATTACH` JOIN over `cache.sqlite`, so hybrid "top-k WHERE tag/type/date" is one JOIN. The MCP **`vault_search`** tool fuses Tantivy lexical + vector hits via **RRF** (k=60, ADR 0018 §8) in `LocalOps`, degrading to lexical-only when no `embeddings.db` exists. Observability: a `stage=vector_search` tracing span, per-vault rolling p50/p95 latency, `GET /api/v/{vault}/embeddings/stats`, and an `embed_metrics` daily trend table are the early-warning system for the eventual LanceDB switch (#244). **Enablement is per-vault and off by default:** `[embed] enabled` in `vault.toml` gates both the worker and the query path (a disabled vault is lexical-only even if a stale `embeddings.db` exists); the desktop ships an embed-capable sidecar and exposes a per-vault **Settings → Semantic Search** toggle that adapts to the connected daemon's `/api/capabilities` `embeddings.compiled_in` (ADR 0018 §9).
- **VaultState** — Per-vault runtime state held by the daemon: cache, search index, engine, root path, config (ArcSwap), template engine. The cache, search index, and template engine are held behind `Arc` so they can be shared into per-session daemon-hosted MCP handlers (`LocalOps::from_shared`).
- **AppState** — Global daemon state containing all VaultStates and shared config. Also owns the durable transcript store (`transcripts: Arc<TranscriptStore>`) and the durable agent-permission grant store (`permissions: Arc<PermissionGrantStore>`).
- **VaultEvent** — An SSE event broadcast when something changes in a vault: note CRUD, task updates, config changes, cache rebuilds.
- **Agent client (`notesmith-agent`)** — Drives external coding agents over **ACP** via the Zed `agent-client-protocol` crate; the crate owns the wire protocol. A declarative **registry** (`registry.rs`, ADR 0013) is the single source of truth for the five built-in agents — Copilot (`copilot --acp`), Claude (`npx @zed-industries/claude-code-acp`), Codex (`codex-acp`), Gemini (`gemini --experimental-acp`), and OpenCode (`opencode acp`) — each an `AgentDescriptor` with ordered launch candidates and setup hints; `AcpSession` builders consume it. `AcpSession` spawns the agent, runs `initialize` → `session/new` → multi-turn `session/prompt`, and normalizes `session/update` into `AgentEvent`s. The active vault is passed as a `session/new` `mcpServers` entry, modeled by the `McpBinding` transport enum; transport is **capability-aware** (ADR 0012, Decision 2): an **HTTP** endpoint (`/mcp/<vault>` or `/mcp-ro/<vault>`) is preferred when the agent advertises `mcpCapabilities.http` at `initialize` (Copilot's ACP mode rejects client-supplied stdio MCP servers, so HTTP is the only binding it accepts — ADR 0012, 2026-09-02 amendment), with a local **stdio** bridge (`notesmith mcp start`) supplied as a fallback for local daemons when the agent lacks HTTP MCP support. **Permission policy** (`permission.rs`): writes prompt per-call with three allow tiers plus deny — **Allow Once** (allow this single call, remember nothing), **Allow This Session** (allow + remember in the in-memory session state, suppresses re-prompts this session only), and **Always Allow** (allow + remember in the session **and** persist to the daemon grant store so a future session — even after restart — is pre-seeded and never re-prompts) (issue #189); read-only mode allows its (read-only) requests silently since it can only ever expose safe reads. The prompt carries a bounded **`DiffPreview`** (path + old/new text, extracted from the ACP `ToolCallContent::Diff`, capped ~8 KB/side per ADR 0009) so the proposed change is shown before any write. The ACP layer stays **HTTP-free**: `AcpSession::with_granted_tools` pre-seeds the session state from a caller-supplied list of already-granted tool names; persistence is orchestrated by the frontend over REST. **Break-glass** (`acp_client.rs`, default OFF): an app-level toggle that advertises vault-scoped fs read/write + terminal; paths are normalized to the vault root, writes/terminal are blocked in read-only mode. **Context injection** (`context.rs`): a one-time session preamble carries a bounded `VaultSummary` (name, note count, top tags/folders) plus the vault's `.notesmith/skill.md` (caller-provided, missing/blank degrades to summary-only), and each turn carries an `EditorContext` block (active note, selection, open tabs) injected ahead of the user message — all size-bounded. **Model selection** (`model.rs`): `parse_model_picker` normalizes the `session/new` result into a `ModelPicker` — preferring a `configOptions` entry with `category: "model"`, falling back to the deprecated `modes`, `None` when neither (no picker, no error). Notesmith hardcodes no model list; `AcpSession::model_picker()` exposes the options and `select_model()` applies a choice via `session/set_config_option` (or `session/set_mode` for the modes fallback). See ADR 0012.
- **Fact memory (ADR 0021; partially shipped)** — A curated layer of one-claim Markdown notes (`type: fact`) with scope, categorical certainty, provenance, and active/superseded/retracted lifecycle. The ACP agent routes information as fact, wiki, both, or session-only. The current product slice ships MCP `memory_recall`, `memory_list`, `memory_save`, `memory_update`, `memory_supersede`, and `memory_delete` over active non-example fact notes using the existing hybrid retrieval stack plus optimistic preview/apply writes; embedded chat can also attach one configured companion memory vault from a saved daemon connection beside the active vault and steer recall to `scope: vault:<active-vault>` by default. Stale-review UX remains backlog.
- **Transcript store (`notesmith-transcript`)** — Daemon-owned, durable per-vault chat history (ADR 0012 Decision 13). A single SQLite database (`transcripts.sqlite`) in the durable data dir (`XDG_DATA_HOME`/local-data → `notesmith/`) — deliberately **outside** any vault (so it neither clutters nor syncs) and **outside** the rebuildable index cache (`cache.sqlite`, which is dropped on schema bumps/reindex). `TranscriptStore` exposes vault-scoped `create_thread` / `list_threads` / `get_thread` / `rename_thread` / `delete_thread` / `append_message` / `load_messages`; every method is keyed by vault so vault A's history is invisible under vault B. Reads degrade per ADR 0009 (corrupt/partial rows are skipped with a `WARN`, never panic). Reopening a thread re-establishes the ACP child session lazily (the `AcpSession` driver starts on first `send`/`select_model`). The daemon opens the store at startup (`build_app_state` → `transcripts_path()`); the per-vault transcript REST endpoints and the chat UI (`agent/chat-store.svelte.ts`) consume it.
- **Permission grant store (`notesmith-permission`)** — Daemon-owned, durable per-vault store of persisted "Always Allow" agent write grants (issue #189). A single SQLite database (`agent-permissions.sqlite`) in the durable data dir, alongside `transcripts.sqlite` and outside the rebuildable cache. `PermissionGrantStore` exposes vault-scoped `grant` (idempotent) / `revoke` / `is_granted` / `list_granted`, keyed by `(vault, tool)` so vault A's grants are invisible under vault B; reads degrade per ADR 0009 (corrupt rows skipped, never panic). The daemon opens it at startup (`build_app_state` → `permissions_path()`) and exposes it over `GET/POST /api/v/{vault}/agent/permissions` + `DELETE …/{tool}`. Persistence is **frontend-orchestrated**: the chat store fetches grants at session start (pre-seeding the ACP session via `with_granted_tools`) and POSTs a new grant on "Always Allow"; the Rust agent layer never speaks HTTP.
- **VaultWatcher** — A filesystem watcher (notify crate) that detects file changes, classifies them (note vs config), debounces, and emits VaultEvents.

## Hook System

- **Hook** — An external command triggered by a vault event. Receives JSON payload via stdin. Failures never block the triggering operation.
- **Hook Events** — Six events: `on_note_create`, `on_note_update`, `on_note_route`, `on_periodic_create`, `on_task_change`, `on_field_change`.
- **on_field_change** — Scoped to `watch_fields` list. Batched per save (one invocation with all field changes). Each change has an `action` discriminator: `add`, `change`, `remove`.

## Integrations & Jobs (ADR 0025; job runner shipped, Work IQ connectors planned)

- **Connector** — A user-provided external executable (in `.notesmith/connectors/`) run on a schedule by the Job Runner to sync an external work system into the vault. Authenticates itself (env file / OS keychain — Notesmith never stores credentials), writes via the REST API or designated folders, and is idempotent via stable external IDs in frontmatter (upsert on resync). Distinct from the built-in colocated **workers** (embed/ingest/transcribe), which are compiled-in Notesmith CLI subcommands.
- **Job / Job Runner** — A scheduled unit of work declared in per-vault `[[jobs]]` config and executed by a generic daemon scheduler. **Shipped (#280 command jobs, #282 agent jobs + `after`)**: `crates/notesmith-http/src/jobs/` runs `command` jobs (connector subprocesses) and `agent` jobs (`agent = { prompt, allow_writes }` → the daemon shells out to the colocated `notesmith ai prompt <name>`, never an in-daemon ACP session) on `every` (interval) or `at` (time-of-day, tz-aware) schedules with `weekdays_only` and catch-up-on-wake (last-run and last-success persisted in the per-vault data dir); runs get cwd = vault root plus `NOTESMITH_API_BASE`/`NOTESMITH_VAULT`/`NOTESMITH_STATE_DIR`, emit `job.*` VaultEvents, hot-reload `enabled` without a restart, and can be triggered manually (`notesmith job run` / `POST /api/v/{vault}/jobs/{name}/run` — which bypasses `after`; `notesmith job list` / `GET …/jobs` for status, incl. `waiting_on`). Same-day `after` ordering gates a job until every named job has succeeded today; an `at` fire whose day ends with unmet prerequisites is recorded as `missed` (WARN once, never run late), and unknown/self/cyclic `after` references are config errors.
- **Calendar Event note** — An imported calendar record: `kind: event`, upserted by its stable `event_id`, with `start`/`end`, `attendees`, derived `audience`, and `customers` resolved via Domain Mapping. Imported *context*, not the record of the conversation — the meeting note (`kind: meeting`) remains authoritative, linked by `event_id`. Not to be confused with **VaultEvent**, the runtime SSE event type.
- **Transcript Note** — A verbatim record of spoken content as a note: `kind: transcript`, one shared body format (the `notesmith-transcribe` renderer), with `source_type` distinguishing origin (teams / youtube / audio). Shared segments carry `speaker: Option<String>` (Teams VTT supplies `<v Speaker>`; YouTube/audio pass `None`), rendered as `[M:SS] Name: text`. `notesmith transcribe --from-vtt <path|->` is the connector entry point into the shared renderer — a subprocess connector cannot call it directly — and `--frontmatter` merges vault-specific keys (`event_id`, meeting/customer links) without core learning the vault's model. Meeting transcripts are sidecar notes linked to the matching calendar occurrence by `event_id` — never inlined into the meeting note. Calendar event notes persist the Teams `join_url`; because recurring occurrences reuse it, transcript timestamps select the occurrence before assigning `event_id`. The verified matcher compares explicitly UTC-normalized timestamps, leaves out-of-window or ambiguous transcripts unmatched, and requires complete paginated calendar input. Not to be confused with the **Transcript store**, which is agent *chat* history.
- **Domain Mapping** — Customer notes carry a `domains` list field (e.g. `domains: ["acme.com"]`); connectors resolve external attendee email domains to customer wikilinks through it and derive `audience`. Unmatched external domains leave `customers: []` for triage.
- **Managed Section** — A machine-owned region inside a human-owned note, delimited by `<!-- notesmith:section:begin <id> -->` / `<!-- notesmith:section:end <id> -->` markers. Re-runs replace marked sections in place; content outside markers is never touched. Used by the daily-briefing agent job; the convention is generic, not daily-note-specific. **Shipped as config (#288)**: documented in `docs/managed-sections.md`; the golden-vault/work-notes-kit `daily` template carries empty `briefing/*` marker pairs, a disabled-by-default `daily-briefing` `[[jobs]]` entry schedules the `daily-note` prompt, and `skill.md` teaches agents the contract (`tests/golden_vault_prompts.rs` keeps the config valid). **Replacing an interior is a core server-side op**: `notesmith_vault::update_managed_section`, exposed as `POST /notes-section/{path...}` and the `update_managed_section` MCP write tool — it swaps only the bytes between one marker pair, refuses malformed/duplicate/inverted pairs, appends a whole block when the pair is missing, conflicts on a stale hash, and is the one write path that skips the save pipeline so no automatic `updated:` stamp lands (ADR 0025 amendment; prompt-only enforcement was verified insufficient).
- **Work IQ** — Microsoft's workplace-intelligence layer over M365 (mail, calendar, files, people, Teams), consumed via its remote MCP server. Deterministic syncs use it as plain MCP clients (no LLM); judgment tasks attach it to headless agent jobs via `[mcp.servers]`. Raw email is never stored — only agent-written summaries persist.

## Save Pipeline

- **SavePipeline** — Pre-write normalization applied to note content: frontmatter stamping (created/updated timestamps), YAML key sorting, trailing whitespace cleanup. (`notesmith-vault::apply_save_pipeline`)

## Security & Conflict Detection

- **WriteGuard** — An Axum extractor that checks the `Origin` header on write requests. Allows localhost, `tauri://localhost`, `notesmith-app://localhost`, and `http(s)://notesmith-app.localhost` origins; rejects foreign origins.
- **ETag** — A BLAKE3 hash of config file content used for optimistic concurrency. GET returns it; PUT requires `If-Match`.
- **Capabilities** — A server-driven feature flags endpoint (`GET /api/capabilities`) that tells the frontend what the deployment supports (desktop vs hosted, config editing, local path opening). It also carries an `embeddings` block (`compiled_in`/`model`/`dim`) advertising whether the daemon was built embed-capable, which the Settings → Semantic Search section reads to adapt (ADR 0018 §9.3); whether embeddings are actually *on* is per-vault (`embed.enabled` in the vault config), not part of this endpoint.

## Frontend

- **Design Tokens** — Components consume bare semantic tokens (`--bg-default`, `--text-default`, etc.) declared in `ui/app/src/styles/tokens-semantic.css` and mapped in `mode-default.css` / `mode-high-contrast.css`; the legacy `--ns-*` compatibility tokens have been removed. The theme engine contract lives in `ui/app/src/styles/`: the catalog contains only Dark, Light, and Split, `crates/theme-gen` precomputes their CSS ramps, and those primitives (`--neutral-*`, `--blue-*`, etc.) map into semantic tokens. Catalog entries also provide explicit semantic surface/border overrides for design-critical chrome instead of relying on generic neutral-ramp steps. Split carries a separate explicit light editor palette and editor semantics inside dark outer chrome. Components must reference the semantic layer instead of defining ad-hoc colors.
- **Theme System** — Theme state lives in `localStorage` under `notesmith:theme` and round-trips through vault config `[appearance]` as `{ theme, followSystem, darkTheme, lightTheme, visualMode }`. A blocking inline script in `app.html` resolves and migrates the active theme before paint, applies layered `data-theme`, `data-tone`, and `data-mode` attributes on `<html>` to prevent flash, and `theme.svelte.ts` keeps those attributes in sync at runtime.
- **Settings Page** — A dedicated `/settings` route with left sidebar navigation and right content area for editing vault config in-app. Sections: General (name, homepage, capture folder/template), Daily Notes, Editor, Git, Hooks, Appearance (compact Dark, Light, and Split workspace previews with live hover preview, optional Dark/Split system pairing, and a high-contrast toggle). Per-section Save/Revert with ETag-based conflict detection.
- **Right Dock** — A single collapsible right-side dock (`⌘\`, `RightDock.svelte`) presenting one **unified underline tab row** — **Metadata / Links / TOC / Chat** — that drives both the dock segment and, within Context, the active sub-tab. The first three tabs show the **Context** rail; **Chat** shows the agent panel. The active segment persists per vault in `localStorage` (`notesmith:dock-segment:<vault>`) and the active Context sub-tab in `notesmith:rail-tab:<vault>` (helpers in `ui/app/src/lib/right-dock.ts`: `loadDockSegment`/`saveDockSegment`, `loadRailTab`/`saveRailTab`, `dockTabs`, `dockTitle`). Both surfaces share one column so the editor is never squeezed by two stacked panels; the workspace-chrome toolbar shows the active note's basename (full path on hover) and right-justifies the collapse toggle, while a ✦ shortcut appears **only when the dock is collapsed** to reopen it directly on Chat. The Chat pane is mounted lazily on first activation, then kept mounted to preserve the live agent session across tab switches.
- **Right Rail** — The **Context** surface of the Right Dock: the content area behind the Metadata / Links / TOC tabs, showing **Metadata** (frontmatter key/values, `_`-prefixed keys hidden), **Links** (backlinks + outgoing), and **TOC** (live table of contents from editor headings with click-to-scroll and active heading highlight). It is a controlled component — the active tab is owned and persisted by the Right Dock — and surfaces a subtle in-content "Refreshing…" indicator while context loads.
- **Middle Pane** — A resizable panel between sidebar and editor, opened by custom sidebar items to show folder listings or query results.
- **Folder Notes** — Same-name markdown notes (`Folder/Folder.md`) represented by their folder row in FileTree. Folder rows open the hidden folder note from the name control, expand from the chevron, and support creation/rename actions from the context menu.
- **Command Palette** — A fuzzy-searchable overlay for executing commands (⌘K / ⌘P). Shows footer hints for keyboard navigation and can switch into a theme-picker sub-mode that previews catalog themes before confirmation.
- **Input Palette** — A sequential multi-step input overlay (same chrome as Command Palette) used for note creation, capture, and template instantiation. Supports text input and fuzzy list picker modes. Replaces `window.prompt()` which is broken in Tauri's WKWebView.
- **Toast Stack** — Non-blocking corner notifications (success/error/warning) with auto-dismiss. Replaces `window.alert()`. Managed by `toast-store.svelte.ts`.
- **Quick Switcher** — A fuzzy note search overlay for rapid navigation (⌘O).
- **Vault Menu** — Browser-only dropdown anchored on the vault name in the workspace chrome (`VaultMenu.svelte`), exposing Switch Vault, Add Vault, and Settings. Rendered only when the Tauri runtime is absent (`isBrowserVaultMenu`); the desktop app uses its native OS menu and window-per-vault navigation instead, and renders a static label that appends an inline **source pill** after the vault name — "💻 Local" for the local daemon or "☁ <server>" (accent-styled) for a remote one, derived from `vaultSourceBadge` (`badge-view.ts`) on the window's own `window_connection_info`. Pure helpers live in `ui/app/src/lib/vault-menu.ts`.
- **Status Bar** — A 28px bar at the bottom of the app showing: the **connection badge** with diagnostic popover (left), vault name (center), cursor position, word count, and save indicator (right). The badge (`ConnectionSwitcher.svelte`, pure helpers in `ui/app/src/lib/connection/badge-view.ts`) reflects **this window's own** connection (`window_connection_info`): a 💻 local or ☁ remote icon, the server name, and a live/offline status dot for remotes. It does **not** retarget the app and is **indicator-only**: clicking it opens a small popover showing the connection name, kind (Local daemon / Remote server), reachability (live/offline + latency), and the remote URL, plus a "Manage servers…" link to Settings → Connection. Cross-server switching is done from the **File → New Window** menu (which lists each server's real vaults), not the badge. Remote windows also get a "Notesmith — <server>" title. Editor state shared via `editor-status.svelte.ts`.
- **Connection Management** — Desktop-only, **per-window** management of which daemon each window talks to (ADR 0017). The persisted server list (`servers.json` in the app config dir, `crates/notesmith-tauri/src/servers.rs`) is the single source of truth, edited in **Settings → Connection** (`ConnectionSettings.svelte`, client in `ui/app/src/lib/connection/connection-client.ts`). Each OS window owns its connection via the `WindowRegistry` (`window_registry.rs`); the "New Window" menu lists vaults grouped by server (each row prefixed with a subtle outline source icon — a monitor for local, a cloud for remote, bundled as muted-gray PNGs under `icons/menu/`), and picking one opens a window bound to that server. `servers.json`'s `active_id` is now a **non-destructive default** (drives new-window / menu defaults), never retargeting open windows. Destructive server edits — URL change or removal — are **blocked while windows are open** against that server. Tauri `connection_*` commands list/add/update/remove/test servers; `connection_set_active` only sets the default (does not re-navigate windows). The app is local-only by default and the in-app choice — not the environment — is authoritative. See ADR 0017 (amending ADR 0014).
- **Note Icons** — Notes can set `_icon:` (emoji) in frontmatter to show a custom icon in file trees, tabs, and quick switcher. The Quill Rail Files tree omits the generic document fallback when `_icon` is absent; tabs and the quick switcher retain their generic fallback. `_`-prefixed frontmatter keys are reserved for system/UI use and hidden from metadata panels.
- **Agent Chat Panel** — The in-app AI chat surface (`ui/app/src/lib/components/agent/AgentPanel.svelte`, ADR 0012 Phase 8), surfaced as the **Chat** segment of the Right Dock. Three layers: (1) a transport boundary (`agent/agent-client.ts`) abstracting the Tauri IPC bridge behind an `AgentClient` interface — `TauriAgentClient` in the desktop app, `UnavailableAgentClient` (panel shows a desktop-only notice) elsewhere; (2) a pure reducer (`agent/conversation.ts`) folding the normalized `AgentEvent` stream (user message, streamed deltas, tool call/result, status, done, error) into renderable items, and capturing each assistant message's **vault note sources** (issue #242) from that turn's `vault_search`/`get_note` tool results (`agent/sources.ts`) — surfaced as a per-message **Show sources** control (`agent/MessageSources.svelte`); web grounding is deliberately excluded and stays as inline citations in the message body; (3) a runes orchestration store (`agent/chat-store.svelte.ts`) injecting the client + the per-vault transcript REST client. The panel exposes agent + model pickers, a read-only/read-write toggle (RO by default — writes hard-denied), an "operating on `<vault>`" scope badge, a conversation/thread list, and a write-permission prompt (Allow Once / Allow This Session / Always Allow / Deny) that shows a diff preview of the proposed change when the request carries one (issue #189); the store fetches persisted grants from the daemon at session start and POSTs a new grant on "Always Allow" (`agent/api/permissions.ts`). Tauri `event.listen` delivers a `{ payload }` envelope, unwrapped by `eventPayload()` in `agent-client.ts`.
- **Agent IPC Bridge** — The desktop-only host for the ACP client (`crates/notesmith-tauri/src/agent_bridge.rs`, ADR 0012 Decision 4). Hosts one `AcpSession` per chat session in a `tokio::select!` pump task that multiplexes ACP events (emitted to the UI as `notesmith://agent-event`) against UI commands. Thirteen `#[tauri::command]`s — `agent_list`, `agent_start`, `agent_prompt`, `agent_select_model`, `agent_set_read_only`, `agent_answer_permission`, `agent_stop`, the ADR 0013 discovery trio `agent_diagnostics`, `agent_config_get`, `agent_config_set`, plus the issue-192 runtime-diagnostics trio `agent_diagnostics_log`, `agent_diagnostics_set_verbose`, `agent_diagnostics_clear` — plus the ADR 0016 / #211 `mcp_servers_get`/`mcp_servers_set` pair, bridge JS camelCase ↔ Rust snake_case. The effective agent list merges the `notesmith-agent` registry with the `config.toml` `[agents]` section (`agent_config_get`/`agent_config_set`): a user override wins, `enabled = false` hides a built-in, and custom ids launch verbatim (with `~`/`$VAR` expansion and per-agent env). At startup `agent_path.rs` resolves an augmented `PATH` (login-shell query + curated dirs) so GUI-launched apps can find Homebrew/nvm-installed CLIs. On-demand structured discovery diagnostics live in a sibling module `agent_diag.rs`, whose `agent_diagnostics` command probes each registry agent (bounded `--version` spawn + capped stdout) and returns a step-by-step trace (resolved PATH, dirs searched, per-candidate found/probe, verdict `available`/`not_found`/`probe_failed`, plus a parsed `detectedVersion` and a `versionWarning` when below the registry's optional `minVersion` floor). A process-global, bounded **runtime diagnostics log** (`notesmith-agent` `diag_log.rs`, `AgentDiagnosticsLog`) records recent agent errors always and — when its verbose toggle is on — a "wire-ish" log of the ACP messages the bridge mediates at *our* boundary (outgoing prompts, emitted events, permission/fs/terminal requests); it cannot capture the raw JSON-RPC bytes, which the `agent_client_protocol` crate owns. Write-permission requests surface as `notesmith://agent-permission` (carrying the bounded diff preview) and are answered via a `oneshot` channel (defaulting to Deny); `agent_start` accepts the frontend's `persistedGrants` to pre-seed the session, and `agent_answer_permission` maps both `allow_session` and `allow_always` to the in-session `AllowAlways` (the daemon grant store is written separately by the frontend). MCP is bound to the local daemon's `/mcp[-ro]/<vault>` HTTP endpoint; the vault root comes from `GlobalConfig`. The user's enabled external MCP servers from the global `[mcp]` config (read via `mcp_servers_get`/persisted via `mcp_servers_set`, managed in **Settings → MCP Servers**) are converted to `McpBinding`s and advertised alongside the vault binding through `AcpSession::with_extra_mcp` (ADR 0016, issue #211); the built-in vault tools are always present and non-removable. The Svelte panel and the bridge are validated end-to-end by headless Playwright flows (`ui/app/e2e/agent-chat.spec.ts`, `agent-picker.spec.ts`, `agent-settings.spec.ts`) that mount the real components with the bridge + transcript endpoints stubbed.
- **Customizations (personas / skills / instructions)** — User-authored `*.md` files discovered by the daemon (`crates/notesmith-customization`, ADR 0016, issue #210) from a vault's `.notesmith/{agents,skills,instructions}/` folders and the global `~/.config/notesmith/` equivalents (project overrides global by file-stem id; malformed files are warn-and-skipped per ADR 0009). Each file carries optional YAML frontmatter (`name`/`description`, plus `backend`/`model` for agents) and a markdown body. Served at `GET /api/v/{vault}/customizations` so discovery works against a remote daemon, and consumed by the chat store (`agent/chat-store.svelte.ts` + the pure `agent/persona.ts`). A **custom agent is a persona**, not a separate CLI: selecting it (via the panel's persona picker or a leading `@persona-id` mention in the composer — session-switch routing, issue #212) applies its `backend`/`model` and contributes its body to the one-time session preamble, alongside always-on discovered **instructions**; the assembled, length-capped preamble is passed to `agent_start` as `preamble` and injected via `AcpSession::with_skill`.
