Who does the “thinking” when memory is merged?

Chat-LLM-in-app (Obsidian Copilot) vs. pushing the work to the calling ACP agent (Notesmith / ADR 0015)

The one-sentence version. Merging memory facts intelligently (“user likes tea” + “user now prefers coffee” → keep coffee) requires an LLM to reason. The only question is whose LLM does it: the app runs its own LLM to do the merge (Obsidian Copilot), or the app stays dumb and lets the user’s already-connected agent (Copilot, Claude, Gemini…) do the reasoning and hand back the result (Notesmith).

Why an LLM is needed at all

Storing a fact is easy — just append a line to a file. The hard part is de-duplicating and resolving conflicts so the memory doesn’t rot into a pile of contradictions. That needs judgement:

Before: - User drinks tea in the morning - User is based in Seattle New fact to add: "Actually I switched to coffee" After (a smart merge): - User drinks coffee in the morning - User is based in Seattle

A plain database can’t decide that “switched to coffee” replaces the tea line rather than adding a fourth contradictory bullet. Only a language model reasons that out. So both designs agree an LLM is required — they disagree on where it lives.

The daemon never runs a model. It only offers tools; the user’s agent — which is already an LLM — does all the reasoning.

The key mental model

Think of the merge as a chore that needs a brain. There are two brains available:

  • Option A hires a brain inside the app (the plugin bundles/pays for its own LLM). The app is a self-contained appliance.
  • Option B borrows the brain you already brought (your Copilot/Claude/Gemini agent). The app is just hands — it fetches and files paper, the borrowed brain does the thinking.

Notesmith picks B on purpose (ADR 0015): “the daemon never runs its own chat LLM.” It ships great tools and lets whatever agent you brought do the reasoning — so it works with any agent, needs no API key of its own, and stays simple.

Where Notesmith lands

For #203, the daemon exposes dumb-but-safe tools — memory.save, memory.recall, memory.list, memory.delete — over an inspectable markdown file. The reasoning parts (deciding what’s worth remembering, and merging/conflict-resolving on save) are done by the calling ACP agent, because per ADR 0015 the daemon won’t run a chat LLM.

Bonus: Notesmith can make memory.recall smarter than Obsidian’s “dump the whole file into the prompt” approach by backing it with the existing embeddings — so recall scales past a fixed buffer without needing an LLM at all.
